# v1.0.8 — Only create manual groups from the right-click menu

## User-facing changes

- **Permanently remove drag-to-create manual groups.** No ordinary tab-to-tab grouping on hover or release; Zen/Zia owns all native tab sorting and drop interactions.
- Retain the existing multiselection workflow: select two or more eligible ordinary tabs, open the tab context menu, and choose **建立群組**. This option is renamed from **建立普通群組**.
- Remove manual grouping drag-event listeners, candidate-state/timers, the horizontal progress bar, favicon-pair overlays, and any temporary hiding of native tabs or close buttons.
- **Remove the Sine settings gear.** Delete `preferences.json` and the `theme.json.preferences` pointer. The removed group-hold duration has no replacement control or runtime pref reader.
- Existing manual groups remain ordinary native `tab-group` elements and keep their persisted name/icon ownership, neutral styling, collapsed previews and restoration. Background-tab drag sorting, site organization and undo/snapshot features remain unchanged.

## Verification

- JS syntax, version/metadata gates and Node tests validate that no manual group script registers dragstart/dragover/drop/dragend listeners, no obsolete drag overlays/styles/preferences exist, and the renamed menu action creates an unpinned native group only for a valid multiselection.
- Native Zen+Zia tests verify existing manual-group creation/restore and that the right-click-only module has no drag preview.
- Physical macOS acceptance: try moving tabs up/down one or more slots (they should only sort), select multiple tabs and choose **建立群組**, confirm no Sine gear and correct group preview/restore.

## Rollback

Reinstall v1.0.7 if the removed functionality is needed, or retain v1.0.8 for the simpler right-click-only workflow. Note that v1.0.7 has known drag interaction regressions and is not recommended for everyday sorting.
