# Zen Site Folders v0.9.3 — native background drag and independent colour ownership

## Changes
- Preserve the working v0.9.2 background drag JavaScript **byte-for-byte** and default it on; remove the user-facing Sine checkbox, while keeping the existing `zen.sitefolders.background_drag.enabled` about:config override as an emergency kill switch (default true).
- Remove Site Folders' selected-tab colour dialog, tab right-click command, colour preference reader and global Zen/Zia tab colour CSS. HDR Guard v0.4.5 now owns that separate UI feature; the original saved preference `zsf.selected-tab-color.v1` remains untouched, so colours and transparency migrate without reset.
- Keep all group-specific menus, animations, SessionStore handling, live sorting, Zia preview cards, and Split View logic unchanged.
- Remove the former colour editor tests from Site Folders. HG carries the colour editor regressions after migration.

## Validation
- Node regressions passed. The background drag script's Git blob is identical to v0.9.2 (`2bf96b968f918d47f66adf41f967b6c3d66d7f07`), so this release does not change its drag behaviour. HG v0.4.5 independently owns the selected-colour UI.
- The pre-existing headless Zen/Zia native drag check still fails because the synthetic browser driver does not deliver a native `drop` event; macOS hardware testing is not performed here. Do not interpret the native check as a successful end-to-end sort test.
- Real macOS/Zia/HG/Sine acceptance is still needed for non-modal colour dialog blur and tracking, especially SDR/HDR composite transitions.

## Rollback
- Disable `zen.sitefolders.background_drag.enabled` in about:config if native drag starts misbehaving; re-enable to restore it. The UI checkbox is intentionally absent.
- Full downgrade: v0.9.2, SHA `2beddbaa9c45f65b3ba87c0d180c36e4c56f9e26`. Its selected-colour menu was owned by Site Folders; disable HG v0.4.5's equivalent UI before switching back to avoid duplicate commands.
