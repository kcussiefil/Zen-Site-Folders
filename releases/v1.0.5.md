# v1.0.5 — Native reorder handoff and cleaner manual-group preview

## Changes

- Restore natural Zen/Zia neighbour avoidance for manual tab sorting. Crossing a hovered target's *far* 70% boundary (dragging downward), or its upper 30% boundary (dragging upward), with just 2px hysteresis, permanently yields the remainder of this drag to native sorting. The next tab cannot restart a group candidate and block the reorder.
- Entering the far-side sort zone directly also latches native sorting, without requiring a preview to have appeared first.
- Keep the native dragged tab hidden only while the manual group preview is active; canceling the preview, crossing into sorting, releasing or escaping restores it immediately. Remove the mod's redundant `dataTransfer.setDragImage` override and leave the OS drag picture to Zen/Zia.
- Reduce favicon pair overlap from 7px to 2px so both site icons are distinguishable.
- Display Zen's default manual-folder SVG in white on the `新群組` progress row and on the resulting uncustomized manual group. Website favicons and custom group icons retain their native colors. Preserve asleep-state opacity for the default folder icon.
- Preserve the original two fixed preview rows, the 150ms stability gate, editable 1.2-second default hold and dragged-source-first group member order.

## Compatibility / known limitations

- This applies only to eligible ordinary standalone tab-to-tab drag grouping. A drag that has switched into sorting cannot create a manual group until the next drag gesture, intentionally preventing immediate re-capture.
- Native OS/Gecko drag images are created when drag starts; they cannot reliably be changed mid-gesture. Removing this mod's override lets Zia control its own visual; a profile with Zia's drag visual disabled may show Zen's native drag picture.
- User testing on macOS with the installed Zen/Zia versions is still necessary. Native CI tests use synthetic browser drag events rather than physical trackpad input.
- Previously observed headless background held-drag driver failures (no `drop` event) are unrelated to this manually scoped change and remain separately documented.

## Verification

- Node tests: upward/downward far-edge crossing, direct far-edge entry, native sorting lock through subsequent tabs, no preview DOM leakage, source-row restoration, 2px favicon overlap, no additional `setDragImage` override, default folder white CSS scoping.
- Native Zen+Zia: complete manual native group creation, visible default folder styling, root-fixed preview position and cleanup.
- Real macOS: drag A→B→C through centre, drag B→A upward, and verify native avoidance resumes promptly without a second hold. Confirm no extra cursor-following X during preview, default folder white and both favicons visible.

## Rollback

- Reinstall `v1.0.4` from Sine or GitHub Releases, or disable manual drag grouping via `zen.sitefolders.manual_group_drag.enabled=false` in `about:config`. Other Site Folders features remain available.
