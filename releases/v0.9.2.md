# Zen Site Folders v0.9.2 — Background drag selection recovery

## Why this version
Real macOS trackpad testing reported that v0.9.1 could still activate background/discarded tabs during a drag, and some drags returned to their original position before the button was released. v0.9.1 was not accepted on the user's system.

## Changes
- Arm background-tab selection protection on pointerdown, preserve it across a later retargeted mousedown, and resolve source via the full composed event path instead of rejecting overlay targets outside the strip.
- Recover the native dragged source even if the corresponding mousedown handler was missed.
- Detect and rewrap the native selectedTab, selectedItem and startTabDrag hooks if another extension replaces them after a previous gesture.
- Preserve ordinary clicking, modifier-click behavior, Split View, snapshot ownership and the existing Zia visual drag implementation.
- Expose a bounded diagnostic trace with window.__zsfBackgroundDragV090.debug().trace when zen.sitefolders.background_drag.debug is enabled in about:config. Debug recording is disabled by default.
- Preserve the Sine toggle zen.sitefolders.background_drag.enabled.

## Verification gates
- New Node regressions reproduce retargeted press paths, missing mousedown before native startTabDrag, native accessor replacement after the first drag, and ten consecutive drags including unloaded tabs.
- Native Zen 1.24b integration checks use physical WebDriver-held-pointer input on macOS and Linux and include Zia 2.121.4 and 2.122.4.
- Not equivalent to actual user's physical macOS trackpad acceptance. Real-world confirmation requires dragging different background/discarded tabs repeatedly while held, without activation or mid-hold snap-back, and retaining final location after release.
- Node regressions pass on the final code branch, including pointerdown + retargeted mousedown and a real new click after the previous drag.
- Headless macOS/Linux WebDriver correctly starts and retains native drag while leaving the original tab selected, but cannot produce an actual drop event in this test setup. **Drop placement and physical trackpad behavior remain unverified**; this is not a completed end-to-end test.
- Historical whole-suite comparison has known failures (including safe-split restore behavior), so no unconditional assertion of full CI success is made.

## Rollback
- In Sine, disable "Drag background tabs without activating or loading them" and restart Zen to restore native drag behavior without disabling other Site Folders features.
- If needed, reinstall prior tagged v0.9.1 or v0.9.0, noting both versions have the reported background-drag issue.
