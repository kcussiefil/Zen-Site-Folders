# Zen Site Folders v0.3.6

**Pre-release｜仍需 macOS Zen + Zia 實機驗證**

### 修正：解散群組後分頁順序相反
- 不再直接逐筆呼叫 `gBrowser.ungroupTab` 然後留下 Zen 原生解除順序。
- 先擷取群組原本由上到下的分頁物件及位置，待解除群組後，使用 `gBrowser.moveTabBefore`／`moveTabAfter` 將分頁校正為相同順序。
- 右鍵「解散群組」與還原箭頭「安全拆分」共用相同保序流程，完成後核對順序、成員與釘選狀態。
- 若原生 API 不完整或排序校正失敗，停止或回報部分失敗，不會清除快照。

### 修正：不能辨識分頁、重置後箭頭消失但資料夾還在
- 安全拆分除了快照記錄的舊群組 ID，也辨識本工具的專屬 `zsf-` 群組 ID、`data-zsf-site` 標記及已保存的群組擁有權資料，處理 Zen 恢復工作階段後群組 ID 改變的情況。
- 若還有無法判定擁有權的一般分頁群組，**拒絕清除快照／還原箭頭**，避免分頁夾殘留卻失去拆分入口。
- 救援後先保留快照與箭頭；使用者核對無誤、確認沒有群組殘留後，再次雙指點按箭頭才會把舊快照完整封存並解除鎖定。
- 手動右鍵「解散群組」也先封存、保留主快照，不在可能失敗前先刪除唯一入口。

### 修正：預覽內關閉分頁造成卡片向左移動
- 固定卡片 `left`、`top` 和動畫原點；關閉分頁時不重新執行定位。
- 原生 `TabClose` 及卡片關閉按鈕改成單次合併清單刷新，避免短暫重播進場縮放或向左跳。

### 安全界線
- 分頁原物件保留，不關閉、不重新載入、不釘選。
- 不變更既有 SessionStore 快照格式；不變更網站分類、新到舊排序、開合或原生 Zia 資料夾。
- 測試為 Node 模擬回歸與 GitHub Actions，尚未完成 Zen 實機端到端驗證；建議先備份 Profile 並在測試 Space 驗證。
