# Zen Site Folders v0.7.1 — Reliable opening time after Zen restore

Fixes a race observed on Zen native macOS/Linux test runs: when Site Folders is
loaded **after** the one-shot `AfterWorkspacesSessionRestore` event, the
`startupRestorePending` guard could stay true indefinitely. Consequently all
new tabs would be incorrectly classified as restored and their genuine opening
timestamps would not be written.

- Observe Zen's `gZenWorkspaces.promiseInitialized`, which resolves when
  workspace restoration is complete, including when Site Folders is injected
  after that completion event.
- Keep the existing event observer for normal startup and make completion
  idempotent to prevent late SessionStartup callbacks from re-enabling the guard.
- Preserve existing `zsf-opened-at-real-v1` values; unknown historical tabs
  continue to show an unknown time, rather than fabricating one.
- Retain native `TabOpen` timestamps and independent `zsf-created-at-v1`
  sorting metadata; no polling, tab activation, or reload.
- Extend time-unit regression tests to cover late-loaded modules and a settled
  Zen initialization promise.
- No changes to v0.7.0 Zia preview styling, video colour protection,
  drag-and-drop, folder layout, or stored groups.

## Validation
GitHub Actions must pass JavaScript regression and native Zen + Zia
macOS/Linux suites before merging.
