# v1.0.4 — Isolate manual-group previews from Zia tab transforms

## Changes

- Correct a visual regression in v1.0.3: while dragging one ordinary tab onto another, the **新群組** title/progress and the two overlapping favicon icons could collapse into the same visible row instead of occupying the original upper and lower tab rows.
- Create the two preview elements directly under the browser root (as independent `position: fixed` elements), not inside the source or target `.tab-stack`. Anchor them to the original tab rectangles captured before Zia dragover reordering.
- Reposition both portals only for real sidebar scroll offsets. Do not follow Zia's moving source/target transforms; neutralize any initial transform of the Zia drag source while capturing its natural tab slot.
- Keep the original native rows masked only during the choice, and clean both root portals on cancel, drop, Escape, or destruction. No preview-time DOM reordering.
- Preserve the 150ms stable overlap, adjustable default 1.2s hold, center-zone gating, upward 170ms favicon animation, and dragged-source-first native group order.

## Compatibility / known limitations

- Ordinary standalone Zen tabs only. Nonadjacent target groups retain their single-row choice fallback without hiding intervening tabs.
- Still requires physical macOS touchpad acceptance with the installed Zia version. CI native group-creation checks use synthetic chrome input and cannot prove actual hardware motion.
- Existing background drag headless tests may report an absent `drop` event from their driver; this is recorded separately from the manual grouping checks.

## Verification

- Node regression: v1.0.3 behaviour, root parentage, exact upper/lower initial coordinates, Zia target-shift isolation, scroll offset synchronisation, cancellation and cleanup, and source-first grouping.
- Browser regression: verifies both root-fixed preview nodes are independent of native tab stacks, visible `新群組` and unchanged native group ordering, on Linux/macOS Zen+Zia.
- Manual: test both directions, keep dragging while the 1.2s fill runs, scroll the sidebar, and confirm the rows do not merge or move into each other.

## Rollback

- Restore `v1.0.3` in Sine if needed, or disable only manual drag grouping with `zen.sitefolders.manual_group_drag.enabled=false` in `about:config`.
