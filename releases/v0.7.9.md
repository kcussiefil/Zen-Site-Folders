# Zen Site Folders v0.7.9 — Nested split-view compatibility

## Changes
- Preserve Zen's nested `tab-group[split-view-group]` structure when split panes are moved into Site Folders. The ordinary-folder motion bridge now delegates split-bearing folders to native Zen/Zia instead of applying direct-tab animation bookkeeping that can hide unrelated rows or split tab labels.
- Reconcile selected split panes using descendants rather than `group.tabs` alone, restore expanded containers, and clear only stranded fully hidden inline tab styles when no native tab animation is active.
- Keep a Site Folder containing a nested split from accidentally dissolving when an ordinary member closes.
- Apply the user's selected-tab color to Zia's split group container, where Zia paints its selected background.

## Compatibility / known limitations
- Only Site Folders containing a nested split bypass the ordinary-group motion bridge; other groups keep their existing spring animation and drag behavior.
- Native Zen/Zia remains responsible for split labels, split arrangement and native split animations. No split tabs are ungrouped, pinned or re-created.
- Automated tests cannot confirm the final result on macOS with a particular Zen/Zia/Sine combination. Manual testing is required.

## Verification
- Required: existing Node and Zen/Zia regression suites, plus the new `tests/split-view.test.cjs`.
- On macOS: move a 2- or 3-pane Zen split into an existing Site Folder, expand/collapse it, change the active split pane, inspect all other rows and titles, confirm custom selected color; also check ordinary folder drag and auto-dissolution.

## Rollback
- Return to v0.7.8 through Sine if this changes split/folder behavior; do not use Undo/Restore as a substitute for reverting a MOD version.
