# Zen Site Folders v0.5.7

Includes the native drag candidate and a fix for premature group-animation completion.

- With Zia loaded, member tabs and site groups wait for native drag ownership instead of first hiding the source and painting a competing card.
- Site groups use one accepted insertion into the last painted ordinary-tab gap. Scoped guards cover native move calls and DOM fallback, refuse stale or pinned-area drops, and remove delayed second reordering.
- Delegated dragover reaches Zen's native edge-scroll handling; non-Zia up/down edge-scroll fallback is retained.
- Ordinary groups defer their early width-transition completion notification until the native vertical expand/collapse promise finishes. This keeps Zen's existing overflow auto-scroll guard active during expansion, without scrolling away and then restoring scrollTop.
- The motion bridge still exposes the same whenIdle/beforeMutation contract used by dragging and restore. Rapid animation reversals defer completion to the latest animation. Other/native groups pass through.
- Native drag takeover also recognizes Zia's active-drag marker if its loaded flag is not yet ready.

Targeted validation passed: script syntax; legacy drag-feedback and collapse checks; one-insertion/pinned-boundary/edge-scroll regression checks; premature-completion, rapid reversal, and drag-beforeMutation integration checks. These are controlled Node checks, not physical macOS GUI acceptance. Full CI was not requested or run manually.

Unverified: continuous physical macOS drag/scroll/landing appearance and whether expansion now preserves the clicked header in all layouts. Real native edge-scroll strength and preview synchronization still require GUI acceptance. No claim is made that these visuals have passed.

Organize/restore logic and glow CSS are retained. No other mod or Zen/Zia installation is changed by this GitHub release.
