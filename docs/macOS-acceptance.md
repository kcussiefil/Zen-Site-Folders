# macOS Zen + Zia 實機驗收

v0.3.8 已獲使用者明確指示發布；實體觸控板、畫面動畫與既有工作階段仍未完成使用者實機驗收。以下是發布後保留的驗收步驟，自動測試通過不等於實機已正常。

## 安裝範圍

1. 完全結束 Zen，先備份原設定檔。先在原設定檔的**副本**測試，保留相同 Zen、Zia 與設定；不要刪除 SessionStore、網站整理快照或還原箭頭。
2. 在副本的 `chrome/sine-mods/zen-site-folders/` 放入v0.3.8 的五個 `site-folders*.uc.js` 與 `userChrome.css`。確認 Sine 顯示版本為 0.3.8。不要把舊版收合腳本額外載入 userChrome。
3. 由 `about:profiles` 啟動副本，完全重新啟動該測試設定檔。不要在真正常用設定檔直接貼腳本或清除快照來「修復」。本次工作沒有自動修改已安裝版本。
4. 使用 macOS 1920×1080，記錄 Zen/Zia 版本、測試分支提交碼及載入檔案。其他解析度另列。

## 檢查項目

每項記錄 PASS / FAIL，附有問題時的錄影；驗收尚未執行時記錄「未驗證」。先記下每個分頁的標題與由上到下順序。

| 項目 | 操作 | 必須符合 |
| --- | --- | --- |
| 無目前分頁的資料夾 | 點標題收合、展開各 5 次 | 確實縮成標題；尾端不抖、不留下空白；和上方原生 Zia 資料夾的動畫比較 |
| 有目前分頁的資料夾 | 收合後在資料夾內切換目前分頁，再選外部的分頁 | 目前分頁可見，其他列不堆疊；切換過渡平順，離開後不留高度 |
| 快速反向 | 動畫未完成就連續收、開、收 | 最終狀態和最後一次操作一致，不卡住 |
| 網址列焦點 | 先點網址列，再拖資料夾中第一、中間、最後的分頁 | 三者都可排序，不因切換焦點而失去拖曳來源 |
| 連續排序 | A B C D → C A B D → A B C D，再由最後拖到最前，重複 5 次 | 放手位置與提示一致，等待 2 秒仍不跳到底部 |
| 捲動排序 | 在長資料夾中一邊捲動一邊拖曳 | 捲動後落點仍正確；不要只看提示線 |
| 整個群組 | 把最後一個普通群組拖至普通分頁區最前 | 群組確實移到最前，成員順序不變，不移進釘選區 |
| 拖後立刻解散 | 將資料夾改成 C A D B，放手後立即右鍵「解散群組」 | 外部順序為 C A D B；等待 2 秒仍相同；沒有確認視窗 |
| 多群組安全拆分 | 各自手動排序後，右鍵還原箭頭 | 每個群組的成員順序及群組相對位置保持，外部原生群組不被拆；不跳確認視窗 |
| 快照與箭頭 | 解散／安全拆分後檢查 | 快照仍在、箭頭仍可見；不要為了測試反覆右鍵清除原快照 |
| 還原 | 在另一份尚未執行安全拆分的整理快照上，左鍵還原 | 回到該快照原排列／群組，分頁物件未重建，沒有重新登入或載入 |
| 邊界 | 無效落點、Escape、拖到其他群組、切換 Space、快速再次拖曳 | 不被上一筆校正拉回、不釘選／關閉分頁，原生其他群組行為維持正常 |

若任何一項 FAIL：保留副本與原快照，記錄操作前後順序及錄影，回報測試提交碼；停止後續更新／發布。若要回退，完全結束該測試 Zen，恢復備份的六個程式檔，再重新啟動。不要以刪除快照、關閉重開分頁或轉為釘選來規避失敗。

## 自動重現

```sh
python3 tests/browser/run.py \
  --binary '/Applications/Zen Browser.app/Contents/MacOS/zen' \
  --zia-dir '/path/to/zia' \
  --output native-results/candidate
```

會另開無視窗的空白設定檔，測試後只終止該測試程序。`results.json` 的 `physicalAcceptance: UNVERIFIED` 是刻意保留的狀態。GitHub Actions 同時測試官方 Zen 1.24b 的 Linux/macOS 版本與固定的 Zia 2.114.1；每次報告可由該 Actions run 的 artifacts 下載。
